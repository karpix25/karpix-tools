# Получение статуса всех задач

## 1. Обзор

Эндпоинт `/v1/toolkit/jobs/status` позволяет получить состояние всех задач за определенный промежуток времени. Это полезно для мониторинга системы и управления списком выполненных работ.

## 2. Эндпоинт (Endpoint)

**Путь URL:** `/v1/toolkit/jobs/status`
**Метод HTTP:** `POST`

## 3. Запрос

### Заголовки (Headers)

- `x-api-key` (обязательно): Ключ API для аутентификации.

### Параметры тела запроса

- `since_seconds` (необязательно, число): За сколько секунд в прошлом искать задачи. По умолчанию — 600 секунд (10 минут).

Тело запроса не обязательно.

### Пример запроса

```json
{
    "since_seconds": 3600
}
```

Или без тела:

```bash
curl -X POST \
     -H "x-api-key: YOUR_API_KEY" \
     http://your-api-url/v1/toolkit/jobs/status
```

## 4. Ответ

### Успешный ответ

Список идентификаторов задач и их статусов:

```json
{
    "code": 200,
    "response": {
        "job_id_1": "done",
        "job_id_2": "running",
        "job_id_3": "queued"
    },
    "message": "success",
    ...
}
```

### Ответы с ошибками

- **404 Not Found**: Директория с логами задач не найдена.
- **500 Internal Server Error**: Ошибка при чтении данных.

## 5. Обработка ошибок

- Неверный ключ API: 401 Unauthorized.
- Ошибка доступа к файловой системе сервера: 500 или 404.

## 6. Примечания по использованию

- Полезно для визуализации очереди задач в сторонних интерфейсах.
- Параметр `since_seconds` позволяет ограничить выборку.

## 7. Общие проблемы

- Неверный заголовок авторизации.
- Отсутствие доступа к папке `jobs` на сервере.

## 8. Лучшие практики

- Регулярно опрашивайте этот эндпоинт, если вам нужен список активных задач.
- Используйте фильтр времени для оптимизации производительности.
- Логируйте результаты для отладки.
