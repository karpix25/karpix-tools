# API эндпоинт FFmpeg Compose

## 1. Обзор

Эндпоинт `/v1/ffmpeg/compose` — это гибкий и мощный API, позволяющий пользователям формировать сложные команды FFmpeg, указывая входные файлы, фильтры и параметры вывода. Этот эндпоинт является частью структуры API версии 1.0. Он предназначен для выполнения различных задач по обработке медиа, таких как манипуляции с видео и аудио, транскодирование и многое другое.

## 2. Эндпоинт (Endpoint)

**Путь URL:** `/v1/ffmpeg/compose`
**Метод HTTP:** `POST`

## 3. Запрос

### Заголовки (Headers)

- `x-api-key` (обязательно): Ключ API для аутентификации.

### Параметры тела запроса

Тело запроса должно быть объектом JSON со следующими свойствами:

- `inputs` (обязательно, массив): Массив объектов входных файлов, каждый из которых содержит:
  - `file_url` (обязательно, строка): URL входного файла.
  - `options` (необязательно, массив): Массив объектов опций:
    - `option` (обязательно, строка): Опция FFmpeg.
    - `argument` (необязательно, строка/число/null): Аргумент для опции.
- `filters` (необязательно, массив): Массив объектов фильтров:
  - `filter` (обязательно, строка): Фильтр FFmpeg.
- `outputs` (обязательно, массив): Массив объектов настроек вывода:
  - `options` (обязательно, массив): Массив объектов опций для вывода.
- `global_options` (необязательно, массив): Глобальные опции FFmpeg.
- `metadata` (необязательно, объект): Настройка включаемых в ответ метаданных (thumbnail, filesize, duration, bitrate, encoder).
- `webhook_url` (обязательно, строка): URL для отправки результата через вебхук.
- `id` (обязательно, строка): Уникальный идентификатор запроса.

### Пример запроса

```json
{
  "inputs": [
    {
      "file_url": "https://example.com/video1.mp4",
      "options": [
        { "option": "-ss", "argument": 10 },
        { "option": "-t", "argument": 20 }
      ]
    }
  ],
  "filters": [
    { "filter": "hflip" }
  ],
  "outputs": [
    {
      "options": [
        { "option": "-c:v", "argument": "libx264" },
        { "option": "-crf", "argument": 23 }
      ]
    }
  ],
  "webhook_url": "https://example.com/webhook",
  "id": "unique-request-id"
}
```

### Пример cURL

```bash
curl -X POST \
  https://api.example.com/v1/ffmpeg/compose \
  -H 'x-api-key: YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "inputs": [{"file_url": "https://example.com/video1.mp4"}],
    "outputs": [{"options": [{"option": "-c:v", "argument": "libx264"}]}],
    "webhook_url": "https://example.com/webhook",
    "id": "unique-request-id"
  }'
```

## 4. Ответ

### Успешный ответ

Результат отправляется на `webhook_url` в формате JSON:

- `file_url`: URL загруженного выходного файла.
- `thumbnail_url`: URL миниатюры (если запрашивалась).
- `run_time`: Время обработки.
- `queue_length`: Длина очереди.
... и другие поля производительности.

### Ответы с ошибками

- **400 Bad Request**: Неверные параметры или отсутствие обязательных полей.
- **401 Unauthorized**: Неверный ключ API.
- **429 Too Many Requests**: Очередь заполнена.
- **500 Internal Server Error**: Ошибка при выполнении команды.

## 5. Обработка ошибок

API валидирует параметры, проверяет авторизацию и лимиты очереди. Ошибки в самой команде FFmpeg также приводят к соответствующим уведомлениям в логах и ответах.

## 6. Примечания по использованию

- Массив `inputs` должен содержать хотя бы один файл.
- `outputs` обязателен.
- Параметр `webhook_url` необходим для получения результата асинхронной задачи.
- Рекомендуется использовать уникальные `id` для каждого запроса.

## 7. Общие проблемы

- Недоступные ссылки на файлы.
- Использование неверных или конфликтующих аргументов FFmpeg.
- Переполнение очереди при высокой нагрузке.

## 8. Лучшие практики

- Тестируйте команды FFmpeg локально перед использованием API.
- Следите за нагрузкой через поле `queue_length`.
- Используйте вебхуки для всех операций, так как обработка медиа может быть долгой.
- Реализуйте логику повторных попыток для доставки вебхуков.
| Свойство | Тип | Описание |
|----------|------|-------------|
| file_url | string | Публичный URL загруженного файла |
| filename | string | Имя загруженного файла |
| bucket | string | Имя бакета GCS, куда был загружен файл |
| public | boolean | Доступен ли файл публично |
| content_type | string | Определенный тип содержимого файла |
