# Эндпоинт для нарезки медиа

## 1. Обзор

Эндпоинт `/v1/media/cut` является частью API-приложения Flask и предназначен для вырезания указанных сегментов из медиафайла (видео или аудио) с опциональными настройками кодирования. Этот эндпоинт входит в общую структуру API как часть blueprint `v1`, содержащего различные функциональные возможности для работы с медиа.

## 2. Эндпоинт (Endpoint)

**Путь URL:** `/v1/media/cut`
**Метод HTTP:** `POST`

## 3. Запрос

### Заголовки (Headers)

- `x-api-key` (обязательно): Ключ API для аутентификации.

### Параметры тела запроса

Тело запроса должно быть объектом JSON со следующими свойствами:

- `media_url` (обязательно, строка): URL-адрес медиафайла для нарезки.
- `cuts` (обязательно, массив объектов): Массив вырезаемых сегментов, где каждый объект имеет:
  - `start` (обязательно, строка): Время начала сегмента в формате `чч:мм:сс.мс`.
  - `end` (обязательно, строка): Время окончания сегмента в формате `чч:мм:сс.мс`.
- `video_codec` (необязательно, строка): Видеокодек для кодирования выходного файла. По умолчанию `libx264`.
- `video_preset` (необязательно, строка): Пресет кодирования видео. По умолчанию `medium`.
- `video_crf` (необязательно, число): Значение Constant Rate Factor (CRF). От 0 до 51. По умолчанию 23.
- `audio_codec` (необязательно, строка): Аудиокодек. По умолчанию `aac`.
- `audio_bitrate` (необязательно, строка): Битрейт аудио. По умолчанию `128k`.
- `webhook_url` (необязательно, строка): URL для уведомления вехуком по завершении задачи.
- `id` (необязательно, строка): Уникальный идентификатор запроса.

### Пример запроса

```json
{
  "media_url": "https://example.com/video.mp4",
  "cuts": [
    {
      "start": "00:00:10.000",
      "end": "00:00:20.000"
    },
    {
      "start": "00:00:30.000",

}
```

## 4. Ответ

### Успешный ответ

Успешный ответ соответствует общей структуре ответа, определенной в `app.py`. Пример:

```json
{
  "code": 200,
  "id": "unique-request-id",
  "job_id": "a1b2c3d4-e5f6-g7h8-i9j0-k1l2m3n4o5p6",
  "response": {
    "file_url": "https://example.com/output.mp4"
  },
  "message": "success",
  "run_time": 5.234,
  "queue_time": 0.012,
  "total_time": 5.246,
  "pid": 12345,
  "queue_id": 1234567890,
  "queue_length": 0,
  "build_number": "1.0.0"
}
```

### Ответы с ошибками

- **400 Bad Request**: Некорректный запрос или отсутствующие параметры.

  ```json
  {
    "code": 400,
    "message": "Invalid request payload"
  }
  ```

- **401 Unauthorized**: Ошибка аутентификации API-ключа.

  ```json
  {
    "code": 401,
    "message": "Unauthorized"
  }
  ```

- **500 Internal Server Error**: Непредвиденная ошибка на сервере.

  ```json
  {
    "code": 500,
    "message": "Internal Server Error"
  }
  ```

## 5. Обработка ошибок

Эндпоинт обрабатывает следующие распространенные ошибки:

- Отсутствие или недействительность параметров: Возвращает 400 Bad Request.
- Ошибка аутентификации: Возвращает 401 Unauthorized, если ключ API недействителен.
- Непредвиденные исключения: Возвращает 500 Internal Server Error при сбоях во время нарезки.

Контекст приложения (`app.py`) также управляет очередью задач. Если лимит очереди исчерпан, возвращается ошибка 429 Too Many Requests.

## 6. Примечания по использованию

- `media_url` должен быть доступным URL-адресом медиафайла.
- Параметр `cuts` должен быть массивом сегментов с временем начала и конца в формате `чч:мм:сс.мс`.
- Опциональные параметры позволяют настроить кодирование выходного файла.
- Параметр `webhook_url` позволяет получить уведомление по завершении асинхронной задачи.

## 7. Общие проблемы

- Недоступный `media_url`.
- Неверные или выходящие за диапазон параметры кодирования.
- Пересекающиеся или неверные сегменты в `cuts`.

## 8. Лучшие практики

- Валидируйте параметры на стороне клиента перед отправкой.
- Используйте `webhook_url` для асинхронной обработки результатов.
- Следите за `queue_length` в ответах для понимания нагрузки на API.
- Используйте `id` для отслеживания и отладки запросов.
