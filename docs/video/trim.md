# Эндпоинт для обрезки видео (Trim)

## 1. Обзор

Эндпоинт `/v1/video/trim` является частью Video API и позволяет пользователям обрезать видео, удаляя части в начале и/или конце. Он также предоставляет опциональные настройки кодирования для контроля качества выходного видео. Этот эндпоинт входит в общую структуру API как часть маршрутов версии 1 (`v1`), в категории `video`.

## 2. Эндпоинт (Endpoint)

**Путь URL:** `/v1/video/trim`
**Метод HTTP:** `POST`

## 3. Запрос

### Заголовки (Headers)

- `x-api-key` (обязательно): Ключ API для аутентификации.

### Параметры тела запроса

- `video_url` (обязательно, строка): URL-адрес видеофайла для обрезки.
- `start` (необязательно, строка): Время начала обрезки в формате `чч:мм:сс` или `мм:сс`.
- `end` (необязательно, строка): Время окончания обрезки в формате `чч:мм:сс` или `мм:сс`.
- `video_codec` (необязательно, строка): Видеокодек для кодирования. По умолчанию `libx264`.
- `video_preset` (необязательно, строка): Пресет кодирования. По умолчанию `medium`.
- `video_crf` (необязательно, число): Значение CRF (0-51). По умолчанию 23.
- `audio_codec` (необязательно, строка): Аудиокодек. По умолчанию `aac`.
- `audio_bitrate` (необязательно, строка): Битрейт аудио. По умолчанию `128k`.
- `webhook_url` (необязательно, строка): URL для уведомления вехуком по завершении.
- `id` (необязательно, строка): Уникальный идентификатор запроса.

Директива `validate_payload` в файле маршрутов гарантирует соответствие запроса схеме со всеми ограничениями.

### Пример запроса

```json
{
  "video_url": "https://example.com/video.mp4",
  "start": "00:01:00",
  "end": "00:03:00",
  "video_codec": "libx264",
  "video_preset": "faster",
  "video_crf": 28,
  "audio_codec": "aac",
  "audio_bitrate": "128k",
  "webhook_url": "https://example.com/webhook",
  "id": "unique-request-id"
}
```

```bash
curl -X POST \
  https://api.example.com/v1/video/trim \
  -H 'x-api-key: YOUR_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "video_url": "https://example.com/video.mp4",
    "start": "00:01:00",
    "end": "00:03:00",
    "video_codec": "libx264",
    "video_preset": "faster",
    "video_crf": 28,
    "audio_codec": "aac",
    "audio_bitrate": "128k",
    "webhook_url": "https://example.com/webhook",
    "id": "unique-request-id"
  }'
```

## 4. Ответ

### Успешный ответ

Успешный ответ соответствует общей структуре, определенной в `app.py`. Пример:

```json
{
  "endpoint": "/v1/video/trim",
  "code": 200,
  "id": "unique-request-id",
  "job_id": "a1b2c3d4-e5f6-g7h8-i9j0-k1l2m3n4o5p6",
  "response": "https://example.com/trimmed-video.mp4",
  "message": "success",
  "pid": 12345,
  "queue_id": 6789,
  "run_time": 5.234,
  "queue_time": 0.123,
  "total_time": 5.357,
  "queue_length": 0,
  "build_number": "1.0.0"
}
```

### Ответы с ошибками

- **400 Bad Request**: Некорректный запрос или отсутствующие параметры.
- **401 Unauthorized**: Ошибка аутентификации ключа API.
- **500 Internal Server Error**: Ошибка во время процесса обрезки видео.

## 5. Обработка ошибок

Эндпоинт возвращает соответствующие коды состояния и сообщения при ошибках параметров. Декоратор `validate_payload` проверяет схему данных. При переполнении очереди возвращается ошибка 429 Too Many Requests.

## 6. Примечания по использованию

- Параметры `start` и `end` опциональны, но хотя бы один должен быть указан.
- Параметры кодирования позволяют кастомизировать качество и размер выходного файла.
- Используйте `webhook_url` для асинхронной обработки.

## 7. Общие проблемы

- Недоступный `video_url`.
- Неверные значения параметров кодирования.
- Проблемы с форматом видео или поврежденные файлы.

## 8. Лучшие практики

- Проверяйте URL видео перед запросом.
- Выбирайте настройки кодирования исходя из требований к качеству и размеру.
- Реализуйте механизмы повторных попыток для сетевых ошибок.
- Следите за длиной очереди (`MAX_QUEUE_LENGTH`).
- Используйте лимитирование запросов (rate limiting) во избежание злоупотреблений.
